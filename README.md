# 死神vs火影 Yk修改器 1.0

4399《死神VS火影 3.3》的实时数值修改器。读取 Flash 插件进程内存，实时锁定对局双方，
可分别调整双方的**攻击倍率 / 防御倍率 / 气耗**。

> 仅用于单机 / 本地娱乐，请勿用于任何联机对战。

---

## 功能

| 功能 | 说明 |
|---|---|
| 自动锁定 | 进对局后先按角色自带的“激活招式数”排除模板，再确认战斗属性确实在逐帧变化（区分上一局残留对象），两道判据都满足才锁定，按 x 坐标分 P1 / P2 |
| 攻击倍率 | 1 ~ 20 倍，写入每个招式的伤害倍率 |
| 防御倍率 | 1 ~ 10 倍（引擎限制最低受击系数 0.1，即 10 倍封顶） |
| 气耗 | 1.0 = 正常；0.5 = 只花一半；0 = 锁气 |
| 换人跟随 | 一方阵亡后，另一方保持锁定，替补上场自动补位 |
| 对局结束判定 | 只剩一人且其招式数骤减 → 判定本局结束，自动清空 |
| 重扫（完整重置） | 一次清空所有锁定、缓存与热点区域，等同重启修改器（滑块数值保留） |

---

## 使用

1. 用 360 浏览器或搜狗浏览器打开游戏，进入对局
2. 双击 `启动Yk修改器.bat`
3. 看到 `锁定: P1=0x... (xx条)  P2=0x... (xx条)` 即可拖动滑块调整

### 权限说明

| 浏览器 | 是否需要管理员 |
|---|---|
| 搜狗浏览器 | 普通权限即可 |
| 360 安全浏览器 | **需要管理员**（它的 Flash 进程是受保护进程，普通权限读不到内存） |

启动脚本会自动请求管理员权限，点「是」即可。

---

## 已知限制

- 只支持 **32 位 Flash 插件**（`pepflashplayer32*.dll` / `NPSWF32*.dll`）
- 锁定/补位不再等招式表；新角色的攻击倍率需等招式表懒加载（约 1~2 秒）后才完整生效
- 对局结束后最长约 4 秒才会自动解锁
- 仅适配《死神VS火影 3.3》

## 版本

- **1.2.4** — 修复严重误锁：还没进对局、没选角色时也会锁到两个对象。**根因**：1.2.3 引入的 `+0x78` 激活招式数只能区分“模板池（固定值 0/30/61）”和“战斗实例（动态值）”，但上一局结束后残留在内存里的战斗实例不会被销毁，其字段仍保留残血、残气和动态招式数（实测非对局状态下仍有三个对象的该值为 12/21），单看这个字段无法证明“当前这一局正在打”。**取证结论**：连续采样证实非对局时全部 44 个候选的血量、坐标、气、能量、招式数在 1.5 秒内完全冻结、零变化，而真对局角色由游戏循环逐帧驱动、至少一个字段一直在变。**新判据（双条件）**：① `+0x78` 落在真人招式区间且非模板值（沿用频次法）；② 新增“帧间活性确认”——持续采样血量 / x 坐标 / 气 / 能量 / 招式数五字段，检测到至少一次帧间变化才认定参战，新对象首帧只建基线、不把首次读取误当变化。活性状态随扫描重建在同地址存活对象间继承，不会每轮重新确认。这样上一局的冻结残留永远进不了锁定栏，真对局角色在开始动作的下一到两个搜索节拍（约几十毫秒）即被锁定。**验证**：假内存端到端六幕（非对局冻结不锁 → 进局活性确认双锁 → P2 阵亡 → 候补首帧不锁、变化后补位 → 二次阵亡 → 终局）全断言通过；真实进程非对局状态下两锁定槽始终为空、零误标；线程模型与零噪音日志保持不变
- **1.2.3** — 把锁人延迟从"等全堆扫描"压到"一次内存点读"，向理论极限再砍一个数量级。**核心是换判据**：旧逻辑必须先把角色的 HitVO 招式表学满 8 条才肯锁，而学招式要扫整堆内存（单次 0.5~0.9 秒），是延迟的总根源。这次改用 FighterMain 自带的 `+0x78` 激活招式数——场上真角色是动态值（实测 12、21），待命对象恒为 0、静态模板池恒为固定大数（30/61），读一个 4 字节整数（约 0.05ms）就能分辨，比全堆扫描快约一万倍。判据做了双保险：硬区间 `1 ≤ 值 < 30` 之外，再叠加频次法——同一值在候选里出现 ≥4 次即判为模板值剔除，版本漂移也能自适应。锁人从此零学习等待，HitVO 学习彻底降级为后台任务，只服务攻击倍率写入；学不满也绝不挡锁，原 8 条门槛保留为字段失效时的兜底。**线程物理隔离**：单 worker 串行时，一次 0.9 秒的全堆学习会把更紧急的找人扫描整个堵在后面。拆成 `yk-scan`（专责找人，轻量高频）和 `yk-learn`（专责学招式，重活慢活）两条独立 worker，各自配独立线程池，互不抢占。**I/O 争用治理**：实测发现两条线程对同一进程的 `ReadProcessMemory` 会在内核层互相拖慢——学习 worker 在有空槽（正在锁人/补位）时主动让路，全堆学习加协作式中止（每扫完一个 8MB 块就检查空槽是否打开，一旦打开立刻收手把带宽还给找人），全堆发现按 2 秒节流且只在"快扫认不出任何有效候选"时才触发，修掉了模板假阳性让全堆发现永不触发、冷缓存卡死的隐患；新增只增不淘汰的"已验证区域"集合，新对局对象落在近期区域时走 10ms 热点即可命中。阵亡去抖 0.3→0.12 秒，空槽扫描节拍 50→30ms。**实测**：数据就绪后空槽→双锁 **p50 50ms / p95 84ms / max 113ms**（1.2.2 同口径 p50 约 220ms、长尾常破 0.5s）；冷缓存首锁稳定 0.57~0.60s（一次全堆发现的固有成本，仅冷启动/换游戏付一次）；候补补位单步 0.1ms 级；状态机五幕（锁两人→阵亡→候补→二次阵亡→终局）全断言通过，连续运行零异常、无噪音日志，全程仅 3 条引擎线程
- **1.2.2** — 修两个实测 bug + 继续压锁定延迟。**候补失效（重点）**：旧代码阵亡时只清 `locked`，死对象仍留在候选池里带着旧峰值/招式表，会顶掉真正的候补，导致"P2 阵亡后补位不发生、最终误走单人骤减退局"。现在阵亡统一走完整 `_release`（踢出池、清旧数据、立即重扫），并引入 3 秒换局宽限期：期间只累积骤减计时不执行释放，给候补留上场时间，宽限一过立即判定，候补来不来都不会卡死终局。**地址复用污染**：同地址被回收给新角色时不再继承旧峰值/`drop_since`，从零学。**延迟**：有空槽即按 50ms 快扫（旧逻辑只看池是否为空，池里有旧对象时拖到 0.5s）、空槽学习重试 0.25→0.12s、全堆回退 0.4→0.3s、有空槽时跳过周期深扫避免 700ms 占住 worker。另按要求删除"慢周期/扫描耗时"噪音日志。实测数据就绪后双锁 0.22s、补位 0.17s，状态机五幕（锁两人→阵亡→候补→二次阵亡→终局）全断言通过
- **1.2.1** — 专砍两个延迟：进局锁人、阵亡补位。实测找人热点 36ms、学招式热点 106ms，慢就慢在频繁掉回 0.5~0.7s 的全堆路径。改动：① 重置后第一扫不再误触深扫（`_last_deep` 重置为 0 导致必走 700ms 深扫，改成重置即起算周期），`重置→有池` p95 从 1.7s 降到 **0.30s**、p50 31ms；② 学习请求拆两路，候选学习和锁定刷新不再互相挤占，worker 用 `Event` 即时唤醒替代 10ms 轮询；③ 候选重试节流 0.5s→0.25s、全堆回退节流 1s→0.4s、池空扫描请求 0.1s→0.05s；④ `ref_hot` 容量 12→24，减少全堆学习；⑤ 扫描线程池模块级复用，不再每次创建销毁
- **1.2.0** — 架构重写，不再打补丁。先清掉历史累积的整份代码重复（两个 `Engine` 类，运行时只有后者生效）和一批死代码（`Calibrator`/`cluster_teams`/`locate_qi`/`_find_bytes_old` 等无引用模块），再把线程模型定死：**引擎线程**只做点读写（判定、槽位、写入、状态），**扫描线程**只做找人/学招式表两类后台任务，热路径上没有任何锁；重置用"代次"作废旧任务，worker 不会再拿着旧句柄崩。实测进局锁定 **1.2s**、重置后重锁 **0.55s**，连续 15 秒边重置边跑零异常，全程只有两条线程
- **1.0.13** — 修复"重开修改器后数值改不动"：写入护栏原来只认 0.1~3.0 的倍率，而上一轮写进去的 20 不在范围内、又没被新实例记录，于是永远跳过 → 现在也接受 1~20 的整数（滑块本来只产出整数）
- **1.0.12** — 修复**防御增益不生效**：实测游戏每帧都会把"正在战斗的角色"的 `defenseRate` 重置回 1.0（写入后 50 ms 就被改回），而原来锁定态 100 ms 才写一次，等于从没生效过。现在只要防御/气耗/攻击不是默认值，节拍自动提到 **15 ms（约 66 Hz）**覆盖每个游戏帧；CPU 占用约 10%
- **1.0.11** — 修三处误判：① `x > 0.5` 改成 `x > -0.5`（角色走到屏幕最左边时 x 接近 0，原来会被误判"阵亡"）② 死亡判定加 0.3 秒去抖，单帧读到异常不再立刻释放 ③ 锁定门槛 5 条 → 8 条（诊断里出现"补位锁到 5 条"，那是清缓存后只学了一半）
- **1.0.10** — 修复快速点「重扫」报 `AttributeError: 'NoneType' object has no attribute 'regions'`：重置改为"UI 置标志 + 引擎线程执行"，不再在扫描进行中把内存句柄置空（实测狂点 30 次 0 错误）
- **1.0.9** — 新增 ESC 退局判定：两人都在时，**双方招式数同时骤减**到峰值的 1/3 以下并持续 **3 秒** → 判定退局（按 ESC 退出不会掉血，原来的规则抓不到）；锁定瞬间即记录招式峰值，秒退也能判
- **1.0.8** — 进程退出的被动检测：不再靠"每秒枚举一次进程"发现插件崩溃，只要有一次读内存失败就立刻释放句柄、下一 tick 重连（实测 5 次强制断线重连，0 错误）
- **1.0.7** — 节拍优化：搜索态 tick 100 ms → 20 ms（锁定态仍 100 ms，不浪费 CPU）；`connect()` 由"每 tick 枚举进程"改为"每秒一次"（原来单次 36 ms，占满整个节拍）；搜索时每次最多重抓 3 个候选的招式表，深扫间隔 5 s → 15 s
- **1.0.5** — 扫描并行化 + 热区持久化：`find_values` 用 8 线程从 751 ms 降到 367 ms；热区表写入 `yk_cache.json` 并绑定进程实例，**重开工具后首次锁定从 1.4 s 降到约 20 ms**（游戏进程换了则自动丢弃缓存）
- **1.0.4** — 取消"本局结束 → 找下一组"之间的缓冲：角色一释放就清零所有节流计时器，下一个 tick（0.1 秒）立刻重新扫描并锁定下一组；搜索不再有 0.8 秒间隔
- **1.0.3** — 去掉界面上的「自动应用」「只写防御」两个开关，默认始终写入内存，界面更干净
- **1.0.2** — 取消"排除上一轮地址"的规则：练习模式里角色会被原地复活（地址和属性都可能完全相同），不再拦住它；防误读仍由"释放即清缓存"保证
- **1.0.1** — 修复启动顺序问题：先开修改器再开游戏、或先开游戏再开修改器，都能自动识别，不用再点「重扫」
